# 第 2 章：分帳核心邏輯與餘額演算法

## 1. 分帳模式與底層資料結構

共同記帳系統必須精確處理各種消費分攤情境。本系統底層支援三種標準分帳模型：

### (1) 均分模式 (Equal Split)
- **情境**：雙方平分此筆花費（例如：晚餐 $500，各負擔 $250）。
- **計算公式**：
  $$P_{\text{your}} = \text{round}(\text{Amount} / 2), \quad P_{\text{partner}} = \text{Amount} - P_{\text{your}}$$

### (2) 比例分帳模式 (Ratio Split)
- **情境**：依據雙方協議的權重分攤（例如按薪資比例 6:4 分攤水電房租）。
- **計算公式**：
  $$P_{\text{your}} = \text{round}(\text{Amount} \times r), \quad P_{\text{partner}} = \text{Amount} - P_{\text{your}}$$

### (3) 不等額與代墊模式 (Unequal / Advance Payment)
- **情境**：某一方現場全額刷卡，但消費內容包含個人自用物品（例如買生活用品 $1,000，其中 $300 為個人專用，其餘 $700 平分）。
- **資料模型**：解構「誰出資（實付）」與「誰享受（應付）」。

## 2. 雙人結算抵銷演算法推導

記帳系統最核心的指標為：**「現在誰該給誰多少錢？」**

### 淨餘額 (Net Balance) 數學公式
定義：
- $N$：歷來共同支出記錄總筆數
- $A_{\text{your}}^{(i)}$：第 $i$ 筆交易「你實際付出的金額」（實際出資額）
- $P_{\text{your}}^{(i)}$：第 $i$ 筆交易「你應負擔的部分」（消費責任額）
- $S_{\text{partner}\to\text{you}}$：對方主動向你結算還款的累積總額
- $S_{\text{you}\to\text{partner}}$：你主動向對方結算還款的累積總額

則你的當前淨餘額 $\text{Balance}_{\text{your}}$ 公式推導如下：

$$\text{Balance}_{\text{your}} = \sum_{i=1}^{N} \left( A_{\text{your}}^{(i)} - P_{\text{your}}^{(i)} \right) - S_{\text{partner}\to\text{you}} + S_{\text{you}\to\text{partner}}$$

### 餘額狀態判定規則：
1. **$\text{Balance}_{\text{your}} > 0$**：你累計代墊金額大於消費責任，**「換對方付（對方應還你 $\text{Balance}_{\text{your}}$ 元）」**。
2. **$\text{Balance}_{\text{your}} < 0$**：對方累計代墊金額大於消費責任，**「換你付（你應還對方 $|\text{Balance}_{\text{your}}|$ 元）」**。
3. **$\text{Balance}_{\text{your}} = 0$**：雙方帳務完美平衡，處於已結清狀態。

## 3. 結算沖銷機制實作

當雙方進行線下現金交付或銀行轉帳時，系統透過寫入一筆獨立的 `settlement` 記錄進行沖銷，**絕不修改或刪除任何歷史交易明細**（符合會計學事件溯源原則）：

```javascript
/**
 * 新增結算記錄
 * @param {string} direction - 結算方向："partner_pay_me" 或 "i_pay_partner"
 * @param {number} amount - 結算金額
 * @param {string} date - 結算日期 (yyyy-MM-dd)
 * @param {string} note - 備註說明
 */
function addSettlement(direction, amount, date, note) {
  checkRateLimit("addSettlement");

  if (!validateNumber(amount, 0.01, 9999999)) {
    throw new Error("結算金額無效");
  }

  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName(CONFIG.SHEET_NAMES.EXPENSES);
  const id = new Date().getTime();
  const currentUser = Session.getActiveUser().getEmail();

  const isPartnerPayingMe = (direction === "partner_pay_me");
  const payer = isPartnerPayingMe ? "對方" : "你";
  const itemDesc = (isPartnerPayingMe ? "[💰結算] 對方還款" : "[💰結算] 我還款") + (note ? " - " + escapeHtml(note) : "");

  // 結算記錄的責任分帳金額 (yourPart, partnerPart) 設為 0
  // 付款人標記為實際出資還款的一方
  const row = [
    date || Utilities.formatDate(new Date(), Session.getScriptTimeZone(), "yyyy-MM-dd"),
    itemDesc,
    amount, amount, "TWD", 1,
    payer, payer,
    0, 0, 0, 0, // 分帳金額為 0，避免重複計入消費
    "結算", "", "", false, "", id,
    "settlement",
    currentUser
  ];

  sheet.appendRow(row);
  const lastRow = sheet.getLastRow();
  sheet.getRange(lastRow, 1, 1, 20).setHorizontalAlignment("center");
  sheet.getRange(lastRow, 1, 1, 20).setBackground("#d1fae5"); // 淺綠色結算高亮
}
```

## 4. 多人情境之貪婪債務簡化演算法 (Greedy Debt Simplification)

當分帳系統擴充至 $M$ 人團體（例如 4 人出國旅行）時，成員之間兩兩欠款會形成高達 $O(M^2)$ 條邊的有向圖。透過**貪婪撮合演算法（Greedy Flow）**，可在 $O(M \log M)$ 時間複雜度內將轉帳次數壓縮至至多 $M-1$ 次：

```javascript
/**
 * 多人債務最小化演算法
 * @param {Object} balances - 各成員淨餘額對照表 { "Alice": 1200, "Bob": -400, "Charlie": -800 }
 * @returns {Array} 最少轉帳次數之交易清單
 */
function simplifyDebts(balances) {
  const debtors = [];   // 負債方 (淨餘額 < 0)
  const creditors = []; // 債權方 (淨餘額 > 0)

  for (const [person, balance] of Object.entries(balances)) {
    if (balance > 0.01) {
      creditors.push({ person: person, amount: balance });
    } else if (balance < -0.01) {
      debtors.push({ person: person, amount: -balance });
    }
  }

  // 由大到小排序，優先消除最大債務與最大債權
  debtors.sort((a, b) => b.amount - a.amount);
  creditors.sort((a, b) => b.amount - a.amount);

  const transactions = [];
  let i = 0, j = 0;

  while (i < debtors.length && j < creditors.length) {
    const debtor = debtors[i];
    const creditor = creditors[j];
    const settledAmount = Math.min(debtor.amount, creditor.amount);

    transactions.push({
      from: debtor.person,
      to: creditor.person,
      amount: Math.round(settledAmount * 100) / 100
    });

    debtor.amount -= settledAmount;
    creditor.amount -= settledAmount;

    if (debtor.amount < 0.01) i++;
    if (creditor.amount < 0.01) j++;
  }

  return transactions;
}
```
